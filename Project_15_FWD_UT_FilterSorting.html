User Testing - Filter & Sorting

 

Background

We have filter and sorting functions in the Lead Management feature since there is a long list of leads (potential customers) and existing customers, making it impractical for agents to manually search for the right person or prioritize follow-ups. These functions allow agents to quickly narrow down the list by criteria such as lead type, status, and sort by date added, or potential value. As a result, the agency can respond faster to high-priority leads, avoid missing renewal opportunities, and focus efforts on the most promising prospects without getting lost in an overwhelming list.

In the current build, the filtering behaviour of the Lead Management module is not consistent across regions:

PH

  • Quick filter (Lead type) - Multiple selection
  • Filter panel - Multiple selection

TKF / FIB

  • Quick filter (Lead type) - Single selection
  • Filter panel - Multiple selection

 

Existing problems

Sorting

  1. The arrow icon changes together with the text changed
  2. It would be confused of what is the exact sequence of the list

Filter

  1. There are 2 chips for the quick filter of individual leads and organization leads, it's single selection
  2. There are the same filter options in the filter panel too when user taps the configure button. But it's multiple selection
  3. The filter options are not consistent between the quick filter and the filter panel
  4. There are other chips in the same screen but they are serve different functions. e.g. there is a defaul selected value on the upper and right ones, it's like a tab instead of filter

 

Purpose

Evaluate the usability of the current filtering function in the Lead Management module, using the existing build of the insurance agent app, with a focus on ease of use and clarity of the UI.

Come up with a better experience for the filtering function and make it more meaningful.

 

Research Questions

  1. How do users usually search or filter the leads?
  2. How do users use the filter in Lead Management?
  3. How often do they use the filter?
  4. Quick filter
    1. Do we need this?
    2. Is it easy to use?
  5. Filter panel
    1. Is it easy to use?
    2. Is it confusing to use the filter panel together with the quick filter?
    3. Single selection or multiple selection?

Insurance agents

For real end users, the warm-up was a few questions to understand their experience first:

  1. Can you walk me through how you usually start your day with leads?
  2. Normally how do you find the leads of different statuses that you want to follow up?
  3. Do you usually filter your leads, or do you scroll and scan?
  4. Which filters do you use most often?
  5. Are there filters you avoid using? Why?
Non end users

Without the context of an agent's daily work, they were given a scenario to role-play before starting:

For this session, please imagine you are an insurance agent working for an insurance company. Your main job today is to follow up on potential customers (called leads), understand their needs, and contact the right people at the right time. Let's focus on this part.

 

Testing Script

Quick filter

  1. What will you do if you want to see individual leads?
  2. What will you do if you want to see entity leads?
  3. What will you do if you want to see the whole list?
Quick filter - Single selection
  • Is it clear to use?
Quick filter - Multiple selection
  • What do you think if these 2 buttons are both in focused state?

Filter panel

  1. If you want to follow up the leads that you've contacted before but haven't created a Sales Illustration yet, what will you do to filter the leads with Contacted status?
  2. What do you expect to do in this panel?
    1. Multiple or single selection for each category?
    2. If the lead type category is single selection, do you expect single or multiple selection on the other categories? Why?
Probing questions
  • "What made you choose that option?"
  • "What were you expecting to see?"
  • "If this were your job, would this feel stressful or manageable?"

Analysis & Findings

Insurance Agents

Agent A - feedback & observation

Agent B - feedback & observation

Key takeaways

  1. Both agents barely track leads in the app - they use Google Calendar or Excel, and search by name rather than filtering
  2. Opposite preferences: Agent A wants multiple selection everywhere to see both lead types with a status; Agent B wants single selection - one lead type at a time, and Contacted / Not contacted as either-or
  3. Both expect lead type to behave the same in the quick filter and the filter panel
  4. Agent B prioritises leads by his own ranking, and would like a ranking label in the list

 

Non End Users

Digital team (P1 - P5)

Other team (P6)

Dev (P7)

IT support (P8)

Key takeaways

  1. The quick filter is easy to miss - P5 and P8 went to the filter panel or browsed the whole list instead
  2. To view all, P6 and P8 tapped "Entity" while on Individual - they expected the quick filter to be multiple selection
  3. Lead type in 2 places is confusing - P1, P6 and P8 want the same behaviour in both; P2, P4 and P7 question why it is in both places at all
  4. Single selection needs an "All" option (P1, P3, P8), selected by default like the other chips on the screen
  5. Multiple selection feels normal for the other categories in the panel, but it is not visually clear - P4 suggested captions for single / multiple selection

 

Insights

5 : 5

Participants were split on single vs. multiple selection for the quick filter, but all 8 who answered chose multiple selection for the other categories in the filter panel.

Same look, different behaviour

Tabs, switchers and filter chips - single and multiple selection - all share the same visual language, so users can't tell how they behave.

No clear default

Without an "All" option, the default state is unclear. 4 participants asked for an "All" option for single selection.

 

Draft Solutions

Solution 1 (Selected)

All multiple selection

Solution 2

By meaning - multiple & single selection

Solution 3

Add "All" - single selection

 

Final Solution

Quick filter

  • Multiple selection, to stay consistent with the behaviour of the filter panel
  • Consider using a different visual language for switchers / tabs and filtering chips

Filter panel

  • Multiple selection for each category, giving users the flexibility to select one or several
  • If more types are added to the categories later, the same behaviour still applies
  • Consider using a different visual language for single / multiple selection
